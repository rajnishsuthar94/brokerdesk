### Deviation: Vitest instead of Jest

The brief asks for Jest. Both official CLIs now generate Vitest: Angular 22 (`@angular/build:unit-test`) and NestJS 12 (`nest new`). NestJS 12 is ESM-only, and Jest's ESM support is still experimental. Forcing Jest onto the API would mean fighting the framework. Vitest uses a Jest-compatible API (`describe`/`it`/`expect`, `vi.fn()` in place of `jest.fn()`), so the tests read the same.

## Frontend state pattern

`core/services/system-status.store.ts` is the reference implementation of this pattern:

- One private `signal<State>()` holds the store's state. It is replaced immutably (`set`/`update` with spreads) and never mutated.
- The store exposes only readonly `computed()` selectors. It exposes no writable signals.
- Async actions call an API service and track `loading / loaded / error`. A request sequence number discards stale responses.
- Components inject the store, read signals in templates, and call actions. Components never use `HttpClient` directly.
- `effect()` is not used to derive state.
- NgRx is not used. Signal stores cover the requirements.

## Dashboard charts (Phase 5)

The charts are small hand-built Angular components (`features/dashboard/components`) with no chart library: column charts and horizontal bar lists in plain HTML/CSS. They follow a data-visualisation checklist:

- **one y axis**, clean ticks, solid hairline gridlines;
- **≤ 24 px columns** with a 4 px rounded data end, square at the baseline, and 2 px gaps;
- **a legend only for 2+ series**; label only the latest value;
- **text never in series colours**;
- **tooltips on hover *and* keyboard focus**, plus a **"Show as table"** view so no value is hover-only.

Colours were checked with a palette validator (CVD separation, lightness, contrast):

| Chart | Encoding | Colours |
|---|---|---|
| New enquiries | One series, one hue | `#2a78d6` |
| Site visits | Scheduled vs completed are nested measures, so two shades of one hue (ordinal check passes) | `#86b6ef` / `#1c5cab` |
| Deals | Emphasis: Won is the story, Lost is gray context | `#2a78d6` / `#a8a69c` |
| Lead sources | Ranked bars, largest first | one hue |
| Pipeline | Bars in stage order, not ranked | one hue |

The lighter marks are below 3:1 contrast. The mitigation is the legend, the value labels and the table view. Overdue numbers carry an icon and a "Needs attention" label, never colour alone.

## Reminders

The header bell polls `GET /dashboard/reminders` every 5 minutes while the app is open, and immediately after any follow-up or visit action. This is **not** push notification. Web push or SMS would need a push service, VAPID keys, subscription storage and a scheduler, none of which are built.

## PWA (Phase 7)

The PWA uses `@angular/service-worker`, enabled in production builds only.

- **Caching (`apps/web/ngsw-config.json`):** the app shell (JS/CSS/index) is prefetched, and icons are cached lazily. `dataGroups` is empty and `/api/**` is excluded from navigation handling, so **no API data (tenant data, signed image URLs) is ever stored by the service worker**. This is verified in Playwright.
- **Banners (`AppBanners`, root component):** an offline notice, and a "new version → Reload" prompt driven by `SwUpdate`, re-checked every 6 h.
- **Install:** manifest and icons are in `apps/web/public`.
- **nginx caching:** service-worker files are served `no-cache`.
- **CSP:** a single `apps/web/security-headers.conf` is used by nginx and by the e2e production server (`e2e/support/prod-server.mjs`). Critical-CSS inlining is off so that `script-src 'self'` holds.

## Tenant isolation & security

Implemented in Phase 2. See [security.md](security.md): four isolation layers (database composite FKs, a per-request membership check, deny-by-default routes, tenant-scoped services), the auth design and the test coverage.

### Frontend auth flow

- `core/auth/auth.store.ts` keeps the access token in a private signal (memory only). At startup an app initializer calls `/auth/refresh`, which uses the HttpOnly cookie to restore the session before the first route is matched.
- `core/auth/auth.interceptor.ts` attaches the token to `/api` calls only. On 401 it performs one shared refresh and retries; if that fails, it ends the session.
- `core/auth/auth.guards.ts` contains UX-only `canMatch` guards. `guestGuard` returns `false`, never a `UrlTree`: it guards a `''` route group, and a `UrlTree` there causes an infinite redirect loop (a real bug caught by Playwright; now covered by `app.routes.spec.ts`).
- Feature stores such as `features/team/store/team.store.ts` are provided by their page, not the root, so their state lives only as long as the feature.

## HTTP conventions

- Base path `/api/v1` (global prefix plus URI versioning).
- In development the Angular dev server proxies `/api` (see `proxy.conf.json`). In production nginx serves the app and proxies `/api`, so the app and API share one origin. Refresh-token cookies can then be `HttpOnly; Secure; SameSite=Strict`, and CORS stays off unless `CORS_ORIGINS` is set.
- Helmet security headers are on, and `x-powered-by` is disabled.
- A global `ValidationPipe` runs with `whitelist` and `forbidNonWhitelisted`.
- Swagger UI is served at `/api/docs`. It is off by default in production.
